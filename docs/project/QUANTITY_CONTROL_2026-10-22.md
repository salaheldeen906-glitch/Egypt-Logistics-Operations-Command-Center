# DAF Logistics — مراجعة الكميات والصرف والاستلام

التاريخ: 22 أكتوبر 2026 — القاهرة. طلب التغيير: `CR-QUANTITY-022`.

النتيجة: تنفيذ في المصدر الحالي ومعاينة تفاعلية معزولة تستخدم مكونات التطبيق ومحركه الفعليين. لم تُنشر التغييرات على الموقع المستخدم فعليًا، ولم تُعدّل بياناته أو حساباته أو إعدادات مشاركته.

## ما ثبت قبل التعديل

- كان إدخال استلام المندوب موجودًا في مسار التحميل المستقل، بينما زر اكتمال المهمة إجراء آخر بلا كمية. لم يُحدد رقم الطلب الذي أبلغ عنه المستخدم؛ لا ندّعي إثبات مساره التاريخي بعينه.
- كان فحص العجز متأخرًا عند الحجز، دون مساعدة كافية لاختيار مخزن بديل أثناء إدخال الطلب أو مراجعته.
- كانت محاولة تجاوز الحجز ترفض دون طلب اعتماد مرتبط. اختلاف تأكيدي المخزن والمندوب كان يوقف التنفيذ دون قرار معالجة قابل للتنفيذ.
- هوية المرحّل لحركة الصرف قد تكون المندوب؛ لذلك لا يصح عرضها باعتبارها تلقائيًا هوية أمين المخزن الذي سلّم البضاعة.

## ما تم تنفيذه

| المتطلب | السلوك القابل للتجربة |
|---|---|
| الاستلام الفعلي | حقل فارغ مستقل يسجله المندوب بنفسه، مع المطلوب الأصلي والمعتمد والمحجوز وتأكيد المخزن والفرق. السبب مطلوب عند الاختلاف؛ المرفق اختياري. |
| سهولة الشاشة | إدخال الكمية يسبق السجل التفصيلي؛ السجل قابل للفتح بالسهم مع الحفاظ على أعمدته. المسؤول الحالي يُعرض باسمه الوظيفي الصحيح. |
| العجز | الرصيد الفعلي والحجوزات والمتاح المؤهل وغير المغطى، مع المخازن والباتشات داخل النطاق. متاح في الإنشاء ومراجعة الطلب وصفوف التوزيع. المقارنة بين المخازن للعرض ولا تغيّر المصدر الفعلي. |
| أهلية البضاعة | استبعاد المنتهي وغير المعتمد قرب الصلاحية، وFEFO. الحجز القائم للمهمة يُحسب تغطية لها ولا يعاد اعتباره مخزونًا حرًا. |
| الزيادة | طلب مرتبط بالبند والوجهة والمهمة والحجز عند تحديدها؛ الكمية السابقة والجديدة والزيادة والسبب والهوية والتوقيت والأدلة محفوظة. محاولة المخزن إعلان كمية أكبر تفتح متابعة واعتمادًا دون صرف تلقائي. |
| الصلاحيات | مدير المشروع ومدير الحركة يستطيعان المراجعة والاعتماد أو الرفض داخل نطاقهما. لا يستطيع منشئ طلب الزيادة اعتماد طلبه بنفسه، بما في ذلك المالك. صلاحيات المالك/المدير التشغيلية القائمة محفوظة؛ لم يُنشأ تفويض استثنائي للاعتماد الذاتي. |
| الفروق | سجل مستقل ومتابعة: جديد، قيد المراجعة، انتظار القرار، معالجة أو رفض بسبب. أحداث المتابعة محفوظة مع التأكيدات الأصلية. |
| التنبيه | قائمة متابعة ظاهرة داخل الطلبات ومهامي، وفلتر زيادات وفروق الكميات؛ ليست خدمة بريد أو إشعارات هاتف. |
| المنصرف | تقرير إضافي داخل التقارير الأساسية، صف واحد لكل حركة صرف فعلية. منفذ صرف المخزن منفصل عن المرحّل ومنشئ الطلب والمعتمد ومؤكد المندوب ومسؤول الفرق. الهوية التاريخية المفقودة تظهر غير متاح. |
| التصدير | XLSX وCSV وفلاتر المشروع والمخزن والمستخدم والتاريخ والمنتج والباتش، مع اختيار الأعمدة وترتيبها وأعمدة تصدير مستقلة. الاعتمادات والمتابعات لا تضاعف المنصرف. |
| سلامة الحفظ | فحص خادم، نطاق المشروع والمخزن والموارد، نسخة البيانات ومفتاح العملية. إعادة الطلب نفسه لا تكرر أثر المخزون؛ التعارض المتزامن يرفض المعاملة الخاسرة بالكامل. |

## أمثلة فعلية من بيئة الاختبار

1. المخزن 100 والمندوب 100: صرف 100 مرة واحدة. إعادة التأكيد لا تنشئ حركة ثانية.
2. المخزن 100 والمندوب 95: يُحفظ الفرق 5 بلا ترحيل تلقائي. قرار مستقل بقبول 95 ينشئ صرف 95 مرة واحدة، ويترك 5 محجوزة؛ لا تُنسب للمندوب كمية لم يؤكدها.
3. بعد صرف 95 ومغادرة المندوب، اكتُشف عدد 93: الفرق الجديد 2 مقارنة بالمصروف 95، مع بقاء التأكيدين الأصليين 100/95؛ لا يُعاد احتساب الفرق القديم 5.
4. الحجز 20 وإعلان المخزن 25: يُحفظ الإعلان ويُطلب اعتماد الزيادة. بعد اعتماد مستقل وفحص توافر الرصيد يصبح الحجز 25؛ ثم يلزم تأكيد المندوب وقرار معالجة قبل الصرف الفعلي مرة واحدة.
5. في توزيع مرتبط باستلام مغلق، قرار فرق 100/95 يصرف 95 مرة واحدة ويحافظ على الاستلام الأصلي مغلقًا. زيادة حصة توزيع 60→70 تخص المهمة وحصتها وحجزها فقط؛ لا تغيّر كمية الاستلام الأصلي ولا تتجاوز المصدر المقبول.
6. طلب 1000، مخزن القاهرة 600 والجيزة 400: المقارنة تُظهر عجز القاهرة 400 والمصدر البديل 400. اختيار المقارنة لا ينقل البضاعة ولا يحجزها.

## حدود المعالجة الحالية

حالات الفقد والتلف واختلاف الباتش والفروق المؤثرة المكتشفة بعد الصرف تظل مفتوحة في انتظار إجراء مخزني مستقل ومعتمد. قرار المراجعة وحده لا يشطب بضاعة ولا يضيف رصيدًا ولا يستبدل الباتش. لم تُنشأ معالجة محاسبية أو سياسة شطب جديدة. البيانات التشغيلية منفصلة عن التقييم المحاسبي.

إنشاء طلب يتجاوز الرصيد يظل مسموحًا باعتباره احتياجًا؛ تظهر التغطية والعجز، ويُمنع الحجز/الصرف غير المغطى. موافقة زيادة الطلب لا تمنح حق اختراع مخزون أو استخدام باتش غير مؤهل. اعتماد الزيادة على حجز محدد يحتاج رصيدًا مؤهلًا إضافيًا في مصدره، وإلا يظل طلب الزيادة معلقًا لحين استكمال المصدر أو إعادة توزيع موثقة.

## المصدر والبيانات وما بقي محفوظًا

سقوف تفويض الحسابات القائمة والمنع الصريح تظلان نافذتين. الحساب ذو سقف لا يتضمن الإجراء الجديد لا يُوسّع تلقائيًا؛ يراجع المالك التفويض عند الانتقال للتشغيل. لم نغير تفويضات حقيقية أثناء التنفيذ.

المصدر هو نفس مشروع Sites `appgprj_6ace37bed1fc8191af88d9705def4ba7`؛ الموقع الحي ما زال v13. فحصت بنية DB وبيانات تعريف مجموعات البيانات للقراءة فقط؛ لم أصدّر قاعدة التشغيل أو المرفقات أو الأسرار. استُخدمت الجداول الحالية approvals/exceptions/handoffs؛ لا ترحيل مخطط أو جداول تشغيل مكررة.

المعاينة تحتوي مشاريع اختبار موضحة بوضوح تحمل الأسماء الأربعة لتجربة النطاق فقط؛ ليست استرجاعًا ولا نسخة من سجلات المشاريع الحقيقية. الحالة والمرفقات التجريبية في الذاكرة، وحماية CSP تمنع اتصال الشبكة، وكل طلب API ينتهي داخل محول الذاكرة بلا أي تحويل للخادم الحي.

الشكل والألوان والقائمة والوظائف والأعمدة والتقارير السابقة والمشاريع والحسابات والصلاحيات خارج هذا النطاق لم تُستبدل. Team Pilot ليس هدفًا لهذا التغيير.

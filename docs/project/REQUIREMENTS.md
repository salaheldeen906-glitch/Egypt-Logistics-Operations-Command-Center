## Decisions / القرارات

- **DEC-001 — Unknown:** Who may resolve warehouse/courier loading mismatch, and whether the affected quantity can be amended/reallocated while another stop departs? Example: planned 60, keeper delivered 60, courier received 55. Current safe first-stage behavior: show 5 difference, retain custody/stock unposted for this confirmation pair, prevent its departure. No stock-balancing fiction or assumed manager override.
- **DEC-002 — Unknown:** Verified independent shared deployment target and resources. Owner selected current repository, not production publication. Current authorized work is a locally gated Command Center path and isolated local D1/R2 test resources; baseline live version 10 remains unchanged.
- **PLAN-001 — Proposed:** First-stage dual loading applies opt-in to simple `delivery` only. Preserve existing legacy/extended request behavior. New pattern must receive operational/design review before generalization to transfer/distribution/collection flows.
- **PLAN-002 — Proposed:** Current-step drafts migrate for the new Command Center journey to per-user central local D1; existing legacy modal drafts remain a recorded gap until generalized. No claim of all-form cross-device draft coverage.

### CR-012 interpretation recorded
Import update mode intentionally updates master names only, matching existing master edit rules. Stock, batch and request updates are excluded; all-or-nothing confirmation remains. CSV protects Excel-like text with an apostrophe; exact text identifiers and typed dates are provided in XLSX. Table preferences are per-account/per-table on a device, consistent with the permitted non-sensitive display-storage exception. Local review is supplementary and is never a shared-persistence acceptance result.

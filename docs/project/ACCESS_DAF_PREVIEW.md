# تجربة ACCESS-DAF المحلية المعزولة

هذه طريقة تشغيل **المصدر المعدّل نفسه بخادم وقاعدة D1 ومرفقات R2 محلية**. ليست ملف HTML يحاكي الصلاحيات، وليست نسخة منشورة أو استعادة لبيانات الإنتاج. لا يتصل المشغّل بقاعدة DAF المستخدمة أو يغيّر إعدادات Sites.

## المتطلبات

- Node.js22.13 أو أحدث وpnpm11.25 كما في `package.json`.
- OpenSSL لإنشاء شهادة HTTPS محلية قصيرة العمر. لا تُرفع الشهادة أو مفتاحها إلى الموقع الحي.
- تبعيات المشروع مثبتة، ثم بناء المصدر المعدّل بنجاح.
- نفّذ من مجلد نسخة المراجعة المعزولة، وليس من بيئة الإنتاج.

```sh
pnpm install --frozen-lockfile
pnpm build
node scripts/preview-access.mjs
```

أول تشغيل يطلب **اسم دخول وكلمة مرور تختارهما أنت** لمالك المعاينة المحلية؛ إدخال كلمة المرور مخفي. كلمة المرور من15 إلى128 حرفًا، ويمكن استخدام مدير كلمات المرور واللصق والمسافات والحروف العربية. لا توجد كلمة مرور اختبار ثابتة أو حساب عام. يحتفظ المشغّل بالهاش المملّح فقط باستخدام نفس صيغة PBKDF2-SHA256 ذات600000 دورة المستخدمة في امتداد الدخول.

يفتح الخادم على `https://localhost:4173/` ويستمع إلى127.0.0.1فقط. المتصفح سيعرض تنبيه الشهادة المحلية الذاتية التوقيع؛ راجع أنها تخص localhost فقط. **لا تثبّت الشهادة كجهة موثوقة على الجهاز** ولا تستخدم شهادة الإنتاج. لا يخفض المشغّل حماية الكوكيز إلى HTTP.

لمنفذ آخر:

```sh
node scripts/preview-access.mjs --port 4180
```

توقيف الخادم يكون بـCtrl+C. بيانات تجربة هذا الجهاز تبقى في `.sites-runtime/access-preview`؛ لا يحذفها المشغّل ولا يعيد تهيئتها عند إعادة التشغيل.

## ما يُنشأ وما لا يُنشأ

يهيئ المشغّل جداول المصدر في قاعدة محلية مستقلة، ومعرّف مالك اختبار واضحًا، ومجموعة بيانات محلية تحمل وصف المعاينة. يربط الملكية التقنية في `settings.owner_id` لهذا الاختبار وحده ثم يربط اسم الدخول الذي اخترته بالهوية نفسها. **لا ينشئ مشاريع Dental/IVF/Oncology/Devices بديلة ولا بيانات مخزون أو رحلات أو أرصدة أو أعضاء تشغيل وهميين.** يمكنك إضافة بيانات اختبار صريحة بنفسك بعد الدخول؛ الفراغ لا يعني أن سجلات موقعك الفعلي حُذفت.

- الدخول يتم بكلمة المرور من النموذج الحقيقي، ويحفظ الخادم جلسة عشوائية محمية.
- يزيل مشغّل المعاينة أي رؤوس هوية Sites يدّعيها المتصفح. لا يوجد مسار عام يمنح هوية المالك.
- حدّث الصفحة، افتح نافذة خاصة وسجّل الدخول مجددًا للتحقق من الاستمرار بين الجلسات.
- من «إدارة الوصول» امنح تفويض جهة تجريبيًا محدد المدة والنطاق، ثم أضف مسؤول عميل واختبره في نافذة منفصلة.
- سجّل خروج العميل ثم اختبر الانتهاء/الإيقاف وسحب الجلسات. حافظ على نافذة المالك حتى تراجع الفارق بين الحساب والجهة.
- لا ترسل كلمات المرور في المحادثة، ولا تضمّن مجلد الحالة أو الشهادات أو ملفات البيئة ضمن حزمة المشاركة.

## تجهيز فقط دون فتح خادم

```sh
node scripts/preview-access.mjs --prepare-only
```

هذا يجهّز الموارد المحلية ويتوقف دون فتح منفذ. يحتاج أول تشغيل إلى اختيار بيانات دخول المعاينة. للأتمتة الخاصة فقط، يقبل `--credentials-stdin` كائن JSON على stdin يحتوي `username` و`password`؛ لا تمرّر كلمة المرور كوسيط shell أو متغير ظاهر في السجل. لا يطبع المشغّل كلمة المرور ولا يكتبها كنص صريح.

إذا تغيّر ملف ترحيل سبق تطبيقه على معاينة قديمة، يرفض المشغّل المتابعة ويحافظ على بياناتها. يمكنك إنشاء حالة مراجعة منفصلة **دون حذف القديمة**:

```sh
node scripts/preview-access.mjs --state-name access-preview-new-review
```

لا تستخدم اسم الحالة القديمة للالتفاف على اختلاف الترحيل، ولا تنسخ ملفات الإنتاج إلى مجلد المعاينة.

وجود هذه الطريقة لا يُعد اختبارًا بصريًا للمتصفح أو جهازًا ثانيًا فعليًا. تُسجَّل الاختبارات التي نفذها المطوّر ودليلها بصورة منفصلة في تقرير التحقق. لا يُنشر هذا المشغّل إلى الإنتاج ولا تُستبدل به آلية استضافة DAF.

## الرجوع وحدود النسخة

إيقاف هذه المعاينة لا يمس الموقع الحي. للرجوع عن **كود التجربة** استخدم نقطة المصدر الأساسية المذكورة في `ACCESS_DAF_2026-10-20.md` أو نسخة checkout مستقلة منها؛ لا تستخدم reset/clean/force-push لحذف شغل محفوظ. تغيير كود الواجهة لا يعيد قاعدة بيانات أو كلمات مرور أو أدوار من نسخة أخرى. بيانات الاختبار المحلية ليست نسخة احتياطية من بيانات الإنتاج، وملفات إعداد البيئة والأسرار ليست داخل حزمة المصدر.
